# Phase 1.5 — 松本市拡張プラン

- **作成日**: 2026-05-29
- **対象**: 松本市の公共スポーツ施設を本サイトに追加
- **目標公開時期**: Phase 1 公開から **2〜3週間以内**
- **公開方針**: B2（全部揃ってから一括公開）

---

## 1. ゴール

長野市と完全パリティで松本市を対応：
- **テニス**コート
- **サッカー / フットサル**施設
- **体育館 / 屋内運動場**（フットサル対応可能なもの含む）

公開時の数値目標：
- 松本市 施設マスタ: **20〜40件**（長野市43に近い水準）
- 空き状況自動取得: **可能な限り全件**
- データ品質: テニスは長野市と同等、サッカー・体育館はベスト努力

---

## 2. スコープ判断（2026-05-29時点の意思決定）

| 論点 | 選択 | 補足 |
|---|---|---|
| 対象競技 | **A3 (テニス + サッカー/フットサル + 体育館)** | ただし技術的支障があれば A2 に縮小可 |
| 公開タイミング | **B2 (一括)** | 段階4まで完成してからリリース |
| 法務スタンス | **C1 (即着手)** | 長野市と同様、明示禁止なし前提でスクレイピング着手 |

### 縮小判断のトリガー（A3 → A2）

以下のいずれかが発生したら A2 に縮小：
- 体育館の予約システム構造が異常に複雑（実装3日超）
- 体育館固有の setting_id 切替が極端に難しい
- 法務的に体育館だけ別問題が見つかった

---

## 3. 想定される技術的論点（長野市との違い）

| 項目 | 長野市（まちかぎリモート） | 松本市（webR） |
|---|---|---|
| URL | `city.nagano.nagano.machikagi-remote.jp` | `yoyaku.city.matsumoto.lg.jp/webR/` |
| システムベンダー | 株式会社ライナフ | 不明（独自 or 共通基盤?） |
| HTML構造 | Rails + Turbolinks | 要調査 |
| JSON API | `/reservation_events.json` あり | 要調査 |
| 認証要否（閲覧） | 不要 | 不要（規則明記） |
| 施設ID体系 | 数値ID (1-200) | 要調査 |
| 旧UI並行 | なし | あり (`/web/`) — 要調査の場合は新UIから |

## 6. リスクと対応

| リスク | 影響 | 対応 |
|---|---|---|
| 松本市予約システムが完全JS依存 | スクレイパー難易度UP | Playwright 利用、所要+1日 |
| 利用規約に明示禁止が見つかる | スクレイピング不可 | 手動更新 or 公式打診 |
| 体育館の予約設計が複雑 | A2 縮小 | 体育館は施設マスタのみ追加 |
| 松本市サイトの仕様変更 | 取得失敗 | スクレイパー保守 |
| 自治体から問合せ | 取得停止 | 24h以内に対応、公式打診へ切替 |
