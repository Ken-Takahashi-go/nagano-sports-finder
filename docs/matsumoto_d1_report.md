## 2. 重要な技術発見

### 発見1: webR は JavaScript描画 (SPA)

`https://yoyaku.city.matsumoto.lg.jp/webR/` を WebFetch すると **タイトルしか返らない** = 本体はJSが描画。
→ **Playwrightでブラウザレンダリング必要**。長野市まちかぎリモートの Stage 2-F と同じアプローチ。

### 発見2: pf489.com 系基盤の可能性 🌟

検索結果に **豊島区も同じ `/webR/` URL構造** で出現：
- 豊島区: `https://www2.pf489.com/Toshima/webR/`
- 松本市: `https://yoyaku.city.matsumoto.lg.jp/webR/`

URL構造の `/webR/` が完全一致 = **共通基盤 (おそらく pf489.com系 or 互換システム)** の可能性大。

**戦略的含意**:
- **1スクレイパーで複数自治体に対応可能**
- Phase 1.6 の **安曇野市 (pf489.com系で確認済)** と統合実装できれば工数大幅圧縮

### 発見3: 公式詳細ページから完璧に属性取得可能

長野市と同じく **「属性は公式ページから、空き状況は予約システムから」のハイブリッド戦略** が使える。
スクレイピング法務リスクを「空き状況のみ」に局所化可能。

## 6. 推奨アーキテクチャ

### スクレイパー設計

```
[Python + Playwright]
    ↓
1. webR にアクセス
2. 施設一覧を取得 (Playwright で描画後の DOM)
3. 各施設の予約カレンダーページにアクセス
4. Network タブで実際の Ajax URL を発見 → 以降は httpx 直接呼び
5. JSON or HTML パース → DBへ
```

長野市 Stage 2-F → 2-G の手法をそのまま流用可能。

### マルチテナント対応 (重要)

```python
# scraper/common/ に共通ロジック
# scraper/nagano_machikagi/  ← 既存(リファクタ)
# scraper/matsumoto_webR/    ← 新規
# scraper/azumino_webR/      ← Phase 1.6 で追加 (pf489 共通基盤の場合は流用可)
```

### DB スキーマ拡張

```sql
-- migration 008
alter table facilities add column external_system text;
alter table facilities add column external_facility_id text;
-- 長野市データ移行
update facilities set
  external_system = 'nagano_machikagi',
  external_facility_id = machikagi_facility_id::text
where machikagi_facility_id is not null;
```
